# Overview

Thank you for your interest in contributing to Zorvax Core.

This project is focused on building a modern, scalable and maintainable FiveM framework designed around professional engineering standards and modular architecture principles.

To maintain consistency and long-term quality across the ecosystem, all contributions should follow the guidelines described below.

---

# Development Philosophy

Zorvax Core prioritizes:

- maintainability
- scalability
- clean architecture
- modular systems
- secure networking
- readable code
- isolated responsibilities

Contributors are expected to align with the framework development standards and architectural philosophy.

---

# Before Contributing

Before opening a Pull Request, make sure to:

✔ Read the documentation inside `/docs`  
✔ Follow naming conventions  
✔ Follow code style guidelines  
✔ Test your changes properly  
✔ Avoid unnecessary dependencies  
✔ Maintain modular architecture standards  

---

# Branch Naming

Branch names should remain clear and predictable.

## Recommended Patterns

```txt
feature/inventory-system
fix/player-loading
refactor/callback-layer
docs/architecture-update
````

---

# Commit Standards

Commits should be descriptive and focused on a single responsibility.

## Recommended

```txt
feat: add callback validation system
fix: resolve inventory synchronization issue
refactor: optimize player manager structure
docs: update architecture documentation
```

---

## Avoid

```txt
update stuff
fix bug
changes
test
```

---

# Pull Request Guidelines

All Pull Requests should:

✔ Solve a clear problem
✔ Maintain code readability
✔ Respect modular architecture
✔ Avoid duplicated logic
✔ Follow naming conventions
✔ Preserve backward compatibility whenever possible

---

# Code Standards

All contributions must follow the official development standards.

## Required

* snake_case naming
* isolated module logic
* server-side validation
* readable code structure
* proper client/server separation
* predictable architecture

---

# Security Standards

Security is a critical part of the framework architecture.

All contributions involving networking, callbacks or state synchronization must include:

* source validation
* permission verification
* payload sanitization
* exploit prevention
* server-side authority checks

Never trust direct client input.

---

# Architectural Standards

The framework is designed around modular architecture principles.

Contributions should avoid:

✘ Monolithic structures
✘ Framework dependency coupling
✘ Global pollution
✘ Cross-module business logic
✘ Unnecessary abstractions

---

# Documentation Requirements

When adding or modifying systems, contributors should also update relevant documentation whenever applicable.

Examples:

* architecture changes
* exports
* events
* configuration
* module behavior
* public APIs

---

# Issue Reporting

When reporting issues, include:

* detailed description
* reproduction steps
* expected behavior
* current behavior
* relevant logs or screenshots

Well-documented issues improve debugging efficiency and development speed.

---

# Code Review Process

All contributions may be reviewed for:

| Validation   | Description                        |
| ------------ | ---------------------------------- |
| Architecture | Modular and scalable structure     |
| Security     | Validation-first implementation    |
| Readability  | Maintainable code standards        |
| Performance  | Optimized runtime behavior         |
| Consistency  | Alignment with framework standards |

---

# Community Expectations

Contributors are expected to maintain a respectful and professional environment.

Constructive feedback, collaboration and long-term maintainability should always take priority over personal coding preferences.

---

# Final Notes

Zorvax Core is intended to be more than a traditional roleplay framework.

The project aims to create a professional infrastructure ecosystem focused on scalability, maintainability and modern engineering practices for the FiveM platform.

Every contribution helps shape the future of the framework.
